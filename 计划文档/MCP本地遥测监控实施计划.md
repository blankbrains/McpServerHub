# MCP 本地遥测监控实施计划

## 目标

将 McpServerHub 从“发现、安装和服务端进程管理平台”扩展为真实用户可用的 MCP 运行监控平台。用户在自己的电脑或服务器运行 MCP Hub Gateway 时，Hub 能安全地收集 MCP Server 的生命周期、工具调用、估算 Token、错误和资源使用情况，并在 Web 端按用户隔离展示。

本次只实现与 MCP 调用链直接相关的遥测能力；不改变市场、配置、现有服务端进程管理和既有使用统计的语义。

## 已确认的现状与缺口

1. `mcp serve` 已能拦截并聚合 stdio MCP Server 的 `tools/call`，但远程上报仅支持单条 HTTP 请求。
2. 现有 `/usage/record` 通过浏览器 JWT 鉴权记录调用，不能作为可撤销的设备凭证使用。
3. 无设备实体、无离线队列、无批量去重、无本地资源采样，也无法区分服务端自托管数据和用户本机遥测数据。
4. 现有监控页的 Token 数据来自 Server 元数据估算，并非真实调用载荷的累计估算值。

## 设计原则

1. **通用性**：以 MCP JSON-RPC stdio 网关为采集点，不绑定 Claude Code、Cursor、Codex 或任一模型提供商。
2. **最小权限**：网页 JWT 只用于创建、查看和撤销设备；本地 Agent 只持有可撤销的设备遥测令牌。
3. **隐私默认保护**：不上报工具参数、工具返回正文、环境变量、文件路径和密钥；只保留事件元数据、计数、时长和错误类别。
4. **离线可靠性**：本地 SQLite 队列先落盘，再批量上传；网络失败指数退避，不影响 MCP 调用本身。
5. **幂等性与隔离**：每个事件有 UUID，服务端按事件 ID 去重；所有监控查询按认证用户过滤。
6. **渐进兼容**：保留现有 `/usage/record` 和自托管监控面板，新增 `/telemetry/*` API，不破坏已有客户端。

## 实施步骤

### 1. 数据模型与迁移

- 新增 `telemetry_devices`：
  - 设备 ID、所属用户、显示名称、令牌哈希、创建/最后在线/撤销时间。
- 新增 `telemetry_events`：
  - 事件 ID、用户/设备、事件类型、Server/工具、状态、调用时长、输入/输出估算 Token、CPU、内存、事件发生与接收时间。
- 增加查询索引，并在现有启动迁移逻辑中同时支持 PostgreSQL 和 SQLite。

验收：

- 新库启动时自动创建表。
- 已存在数据库升级后不丢失数据。

### 2. 设备凭证与遥测接收 API

- 已登录用户可创建、列出和撤销自己的设备凭证。
- 仅创建时返回明文令牌；数据库只保存 SHA-256 哈希。
- `POST /telemetry/events` 仅接受设备令牌，限制批次大小和字段长度。
- 服务端按事件 ID 幂等入库，拒绝已撤销或未知设备。

验收：

- 用户无法查看、撤销或查询其他用户设备和数据。
- 同一事件重复上传只计入一次。
- JWT 不能代替设备令牌写入遥测数据。

### 3. 本地遥测组件与 Gateway 集成

- 新增独立遥测客户端：
  - 本地 SQLite spool、批量发送、网络失败保留、成功后删除。
  - 输入/输出 JSON 的本地 Token 估算，上传前丢弃原始载荷。
  - `server_lifecycle`、`tool_call`、`resource_sample` 和 `heartbeat` 事件。
- `McpGateway` 使用该组件：
  - Server 初始化成功/失败和关闭时上报生命周期。
  - 每次工具调用记录时长、成功状态和输入/输出估算 Token。
  - 后台周期采样子进程 CPU/内存并上报心跳。

验收：

- 未配置遥测环境变量时，Gateway 保持原有行为。
- 上报或 SQLite 故障不会阻断 MCP JSON-RPC 调用。
- 队列在网络恢复后能成功补传。

### 4. CLI 与用户接入

- 新增 `mcp agent` 命令组：
  - `mcp agent config` 生成可放入 MCP 客户端配置的 Gateway 配置片段。
  - `mcp agent status` 显示当前 Agent 遥测配置和本地队列数量。
- 配置通过环境变量传递 Hub 地址、设备令牌和本地状态目录，不将令牌写入项目文件。

验收：

- 命令不需要访问服务端即可生成配置或查看本地队列。
- 运行命令不会把令牌打印到日志或状态输出。

### 5. Web 监控面板

- 已登录用户可在监控页：
  - 创建和撤销设备密钥。
  - 查看过去 24 小时/7 天的调用量、成功率、估算 MCP 载荷 Token、活跃设备和失败数。
  - 按 Server 查看调用、错误、延迟和估算 Token。
- 未登录状态保持现有公共/自托管监控体验，不泄露用户数据。

验收：

- 空数据、加载失败、创建失败、令牌仅显示一次和撤销状态均有明确 UI 状态。
- 前端所有受保护请求使用 Bearer JWT。

### 6. 验证与部署

- 增加单元/接口测试：
  - 设备令牌、撤销、事件幂等、用户隔离、聚合查询。
  - SQLite spool、失败重试和隐私字段不落盘/不上报。
  - Gateway 调用事件的 Token 统计。
- 执行 `pytest tests -q`、针对改动模块的 Ruff、前端生产构建。
- 仅部署到 `djl@172.19.138.78:/home/djl/code/McpServerHub`，重启远程服务并验证健康检查、静态资源和遥测 API 鉴权。

## 非目标与限制

1. 本次记录的是 MCP 请求/响应载荷的本地估算 Token，不宣称等同于 Claude、OpenAI 或其他模型提供商的真实计费 Token。
2. 不采集用户电脑的任意目录、完整日志、工具参数或工具响应；详细审计需要单独的显式授权设计。
3. 不引入 ClickHouse；当前规模先使用 PostgreSQL 聚合，后续在实际写入量证明需要时再迁移分析存储。

## 完成标准

1. 本地 Gateway 在不影响 MCP 请求的前提下可离线缓存并安全上传遥测。
2. 设备令牌可创建、撤销，事件写入具备幂等性和用户隔离。
3. Web 端能展示真实上传的调用、延迟、错误和估算 Token。
4. 全量后端测试和前端生产构建通过，远程服务运行验证通过。
